## 实际交互

使用后台的 Codex 内置浏览器连接本机回环地址上的 noVNC 控制台，操作虚拟机桌面。没有打开主机屏幕共享，也没有连接主机剪贴板。

已实际点击检查以下流程：

- 菜单栏左键展开列表，右键显示操作菜单。
- 列表展开后直接输入搜索，清除搜索，回车打开便签；打开后列表收起。
- 在参考应用中用全局 `⌥⌘0` 展开列表，再点击参考窗口收起列表。便签仍保持打开。
- 从 Dock 返回最近便签，列表不自动出现，左侧参考内容仍可见。
- 开启贴边入口，点击展开与收起，拖到另一侧后自动贴边；拖动没有触发展开。
- 便签折叠为首行标题栏，按钮、菜单及 `⌥⌘K` 恢复完整尺寸。置顶与折叠各自保存。
- 编辑后折叠、展开，仍能撤销折叠前的编辑。
- 正常退出后生成自动备份，再启动恢复保存内容。贴边入口位置也恢复。
- 查看浅色、深色的列表、便签及入口，另查看列表活动与失焦状态。

手动外部点击配合 `JOTLET_MANUAL_WINDOWS=1` 完成了 33 项窗口检查，日志在 `.build/tart-runs/run.Te1Z0U/artifacts/manual-windows2.log`。后续菜单与快捷键检查使用独立构建路径，客机二进制摘要与主机一致。

## 测试工具的注意事项

程序切换应用焦点不能充分模拟对非激活面板的外部点击。默认窗口检查会明确标出这一项需手动执行，不能据此声称外部点击已经通过。

Tart 实验性 VNC 与 noVNC 的 Mac 修饰键映射不同。直接发送 Option + Command 时，客机有时只收到 Command；通过控制台按钮发送完整修饰键，并核对客机按键日志后，快捷键正常触发。这个限制属于远程输入，不能用缺少修饰键的结果判断应用快捷键失效。

客机可能缓存共享目录中的旧文件。不要在虚拟机运行时覆盖同一路径的构建再直接执行。每次测试使用新的共享路径，并复制到客机临时目录。自动脚本已采用这个方式。

## 尚未覆盖

真实多显示器的移动、不同桌面间的拖动和全屏应用组合没有做完整交互验证。便签仍采用 macOS 管理的普通窗口和单桌面置顶，重启后的桌面编号由系统决定。

编辑器与系统剪贴板格式已在客机检查。飞书和系统备忘录更新后可能改变复制的数据结构，实际图文混合粘贴仍需在日常内测中观察。
