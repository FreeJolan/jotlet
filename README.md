# Jotlet

[![CI](https://github.com/FreeJolan/jotlet/actions/workflows/ci.yml/badge.svg)](https://github.com/FreeJolan/jotlet/actions/workflows/ci.yml)

macOS 本地便签。写几句话，贴一张截图，把需要参考的那张留在工作窗口旁边。

## 开始使用

需要 macOS 14 或更新版本。发布包为 Universal 应用，同时包含 Apple Silicon 和 Intel 架构。

从 [GitHub Releases](https://github.com/FreeJolan/jotlet/releases) 下载 ZIP，解压后将 `Jotlet.app` 放入应用程序目录。更新前正常退出旧版，再替换应用。请勿同时运行多个副本，它们会使用同一个资料库。

当前内测包使用 ad-hoc 临时签名，尚未使用 Developer ID 签名或 Apple 公证。从网络下载后，macOS 可能拦截首次打开；请先确认来源和 `SHA256SUMS`，参阅 [Apple 的应用打开说明](https://support.apple.com/en-us/102445)。也可以按下方步骤从源码构建。

便签列表按需展开，打开便签后自动收起。切回应用会回到最近使用的便签；没有打开的便签时才显示列表。便签失焦后仍留在桌面上。

| 操作 | 方法 |
| --- | --- |
| 新建便签 | 菜单栏或全局快捷键 `⌥⌘N` |
| 隐藏 / 恢复已打开的便签 | 全局快捷键 `⌥⌘J` |
| 展开 / 收起列表 | 点击菜单栏图标，或全局快捷键 `⌥⌘0` |
| 从便签打开列表 | `⌘0`，或窗口工具栏右侧的列表按钮 |
| 收起列表 | `Esc`、点击外部，或选择一张便签 |
| 搜索便签 | 展开列表后直接输入，回车打开第一个结果；`⌘F` 回到搜索框 |
| 置顶 | 新便签默认不置顶，点窗口工具栏左侧的图钉开启 |
| 完全收起便签 | 点标题栏右侧箭头，或 `⌥⌘K`；整张窗口消失，内容仍保存 |
| 找回最近收起的便签 | 再按 `⌥⌘K`，或从列表打开；恢复原尺寸、位置和置顶状态 |
| 关闭便签 | 关闭窗口，内容仍保留在列表中 |
| 贴边入口 | 默认关闭。在列表右上角菜单中开启，拖动调整位置，松手后贴到最近的左右边缘 |
| 打开设置 | 菜单栏图标右键 → 设置，或便签内按 `⌘,` |
| 隐藏 Dock 图标 | 在设置中开启；设置会保留，随时可以关闭 |
| 切换已打开的便签 | 进入一张便签后，按 `⌘` + 反引号；加 `⇧` 反向切换 |
| 菜单栏快捷操作 | 右键菜单栏图标，可新建、隐藏便签、切换贴边入口或退出 |
| 移动到其他桌面 | 在 Mission Control 中将便签窗口拖到目标桌面 |
| 勾选清单 | 点工具栏的清单按钮，再点击文字前的方框切换状态 |
| 清单换行 | 回车继续下一项，空子项回车退一级，空根项回车退出 |
| 清单缩进 | 在清单内按 `Tab` 缩进，`⇧Tab` 退一级，也支持选中多行 |
| 切换待办状态 | 点击方框，或在当前项按 `⇧⌘X` |
| 查看图片 | 双击图片放大，右键图片可复制或调整显示大小 |
| 打开链接 | `⌘` 点击链接 |
| 无格式粘贴 | `⌥⇧⌘V` |
| 复制为 Markdown | `⌥⌘C`，或“编辑 → 复制为 Markdown” |
| 粘贴 Markdown | `⌥⌘V`，或“编辑 → 粘贴 Markdown” |

正文支持标题、加粗、斜体、下划线、项目列表、编号列表、清单、链接和图片。格式即时显示。待办使用圆角勾选框，完成项变灰并显示删除线，长文字换行后对齐。勾选时保留编辑光标。复制到普通文本应用后仍用 `☐`、`☑` 表示状态。

贴边入口只在点击时展开列表，鼠标经过不会弹出。单张便签收起后不会留下标题栏。其他已打开的便签不受影响，正在置顶的便签收起后也会完全消失，找回时恢复置顶状态。

隐藏 Dock 图标后，Jotlet 不再出现在 `⌘Tab` 的应用切换列表中，也不展示顶端的应用菜单。可点击菜单栏图标或用全局 `⌥⌘0` 打开列表，`⌥⌘K` 找回最近收起或使用的便签。进入便签后，`⌘` + 反引号仍能切换同一桌面上已打开的便签；格式与备份操作也可从便签工具栏、列表菜单和快捷键访问。

## Markdown 与复制

输入常用 Markdown 语法后，内容会直接变成富文本。

在标题开头按退格，先恢复为正文，文字和前面的换行保持不变。刚输入 `# `、`## ` 后出现的空标题也能直接退格取消。在清单或引用的文字开头按退格，先退一级或退出该格式。空段落里残留的加粗、斜体、等宽、下划线和删除线也可用退格清除。取消格式支持撤销与重做；光标位于文字中间、选中文字时，退格仍按正常方式删字。

| 输入 | 显示效果 |
| --- | --- |
| 行首 `# `、`## ` 至 `###### ` | 标题、小标题，空格后开始输入标题文字 |
| 行首 `- `、`* `、`+ ` | 项目列表 |
| 行首 `1. ` 或 `1) ` | 编号列表，回车继续下一项 |
| 行首 `- [] `、`- [ ] ` 或 `- [x] ` | 空格后变成未完成或已完成的待办；也可用 `[ ] `、`[x] ` |
| 清单中按 `Tab`、`⇧Tab` | 缩进或退一级，回车保留层级，已完成项后新建未完成项 |
| 行首 `> ` | 引用，回车继续，空引用回车退出 |
| `**文字**`、`*文字*` | 加粗、斜体，闭合符号后显示格式 |
| `[名称](https://example.com)` | 可点击链接 |
| 单个反引号包住文字、`~~文字~~` | 等宽文字、删除线 |

粘贴纯文本时，常用 Markdown 会自动排版。来源同时提供富文本或 HTML 时，普通粘贴优先保留其格式；需要解析语法可以用“粘贴 Markdown”。无格式粘贴保留原始符号。Markdown 解析使用系统 [Foundation](https://developer.apple.com/documentation/foundation/nspresentationintent?language=objc)，内容转换为普通字体和段落属性后保存。带代码段的 Markdown 也可粘贴；Markdown 图片链接和表格保留原文，图片仍可直接粘贴或拖入。

复制到飞书、系统备忘录等文档编辑器，优先用普通 `⌘C`。剪贴板同时提供富文本、HTML 和纯文本，接收应用自行选用。HTML 包含标题、嵌套列表、待办状态、引用、等宽文字、删除线、链接和内嵌图片。复制到 Markdown 编辑器或源代码输入框时，可用“复制为 Markdown”。最终可显示的格式取决于接收应用支持哪些能力。

## 保存和恢复

数据位于 `~/Library/Application Support/Jotlet`。

- 每次编辑后约 0.4 秒自动保存，切换窗口、收起和退出时立即保存。
- 正文使用系统 RTFD 格式，图片原始数据随正文保存。
- 保存失败会在便签底部显示提示，保留窗口中的内容；可通过“文件 → 重试保存”重试，也可导出当前便签。
- 删除进入废纸篓，可以恢复。清空废纸篓前会生成完整备份。
- 每 15 分钟以及正常退出时按需自动备份，保留最近 20 份。列表右上角菜单可打开备份文件夹。
- 手动完整备份导出为 `.jotletbackup`。恢复会将备份内容作为新便签加入，保留现有便签；备份内的废纸篓状态也会保留。
- 单张便签导出为 HTML，图片内嵌在文件里，可以独立查看。

## 内测范围

交互和窗口行为已在 Apple Silicon Mac、Tart 的 macOS 26.6.2 中验证。CI 分别在 Apple Silicon 和 Intel 的 macOS 15 虚拟机上执行单元测试、原生编辑检查，再构建并校验 Universal 包。最低系统版本由构建目标设为 macOS 14，真实 macOS 14 设备的完整窗口交互尚未验证。

置顶窗口属于所在的桌面，运行期间可通过 Mission Control 移动。应用会恢复窗口位置、大小和置顶状态；重新启动后，窗口分配到的桌面由 macOS 管理，当前版本不保证恢复原来的桌面编号。全屏应用覆盖没有作为首版能力交付。

复制粘贴验证覆盖纯文本、HTML、RTF/RTFD、Markdown 和系统图片剪贴板。不同应用可能提供不同的剪贴板数据；飞书文档和系统备忘录的实际图文混合粘贴仍应在日常内测中观察。没有跨机器同步或表格编辑工具。

0.2.3 补上标题、清单、引用及空段落内格式的退格退出行为，取消格式时保留文字和段落边界，并支持撤销、重做。

0.2.2 调整了待办勾选框、完成状态和换行对齐，补上 `- [] ` 等快捷写法、清单缩进与引用输入。复制为 Markdown 保留待办状态和层级，普通复制的 HTML 也包含待办、引用和代码格式。

0.2.1 加入设置和隐藏 Dock 图标，单张便签改为完全收起，并用全局快捷键找回。0.2.0 已折叠的便签会按保存的完整尺寸打开。隐藏 Dock 后的应用切换列表、三张便签的窗口循环、设置恢复和连续收起找回已在虚拟机桌面实际检查。界面检查使用一块虚拟显示器；真实多显示器和多个桌面的拖动仍需在日常内测中观察。

0.1.3 修复主窗口失焦后“新便签”按钮不可见的问题，按钮使用系统边框样式和语义文字颜色。已检查浅色、深色外观的活动和失焦状态，以及实际点击新建便签的操作。

0.1.2 加入 Markdown 输入与粘贴、复制为 Markdown，并将新便签改为默认不置顶。普通复制的 HTML 带有标题和列表结构，中文斜体也能保留。已有便签沿用各自保存的置顶状态。

0.1.1 修复了飞书原生编号标题粘贴后编号重复、标题变成正文字号的问题。编号起点及标题样式会保留，保存、复制、撤销和重做也已检查。此前已经粘贴的内容可从原文重新复制。

## 开发

需要完整 Xcode 16 或更新版本（Swift 6），以及 Python 3.9 或更新版本。采用 Swift、AppKit 和 SwiftUI。编辑内核复用 macOS 的 `NSTextView` 与系统富文本、剪贴板和撤销能力，窗口使用 AppKit 管理。

```sh
swift test
./scripts/build.sh               # 当前机器架构，输出 dist/Jotlet.app
./scripts/build.sh --universal   # Apple Silicon + Intel
./scripts/test-tart.sh
```

`swift test` 覆盖富文本及图片保存、备份恢复、无效备份、删除恢复、清空前备份、HTML 导出、写入失败、索引损坏恢复和编号标题粘贴。飞书剪贴板样例仅保留匿名化的 HTML 结构。原生集成检查直接操作编辑器、系统剪贴板、撤销管理器和窗口控制器，使用临时目录并恢复原剪贴板。

窗口测试默认通过 Tart 在独立 macOS 虚拟机里进行，避免打断主机上的工作。首次创建测试虚拟机：

```sh
brew install cirruslabs/cli/tart
tart clone ghcr.io/cirruslabs/macos-tahoe-base:latest jotlet-test
tart set jotlet-test --cpu 4 --memory 6144 --display 1440x900 --no-display-refit
```

`scripts/test-tart.sh` 构建应用，在后台启动虚拟机，运行原生集成检查及跨应用窗口检查，并保存列表的活动、失焦截图，以及浅色、深色便签编辑器截图。窗口检查启动独立的参考应用，核对实际焦点和 WindowServer 中的窗口顺序。测试结束后关闭虚拟机，保留磁盘供下次复用。结果在 `.build/tart-runs/`，截图仍需查看后才能确认外观正确。可通过 `JOTLET_TART_VM` 指定另一台已创建且已关机的测试虚拟机。

虚拟机启动固定使用 `--no-graphics --no-clipboard --no-audio`，不打开主机窗口，不同步主机剪贴板。只共享应用构建产物、测试脚本和结果目录，个人便签不参与测试。`scripts/tart-guest-test.sh` 检查虚拟机共享目录，误在主机运行时会直接退出。首次镜像下载体积较大，之后无需重复下载。

当前内测构建通过 34 项单元测试（存储、格式转换及旧版数据兼容）、100 项原生集成检查和 44 项窗口检查。原生检查覆盖编辑、剪贴板、图片、保存、撤销和重做。外部点击不能用程序切换焦点代替，另在隔离的虚拟机桌面中实际点击验证。当前测试记录见 `docs/TESTING-0.2.3.md`，Tart 首次验证及远程输入限制见 `docs/TESTING-0.2.0.md`。

需要隔离开发数据时，可以设置 `JOTLET_DATA_DIR`。测试入口 `--ui-fixture` 只用于开发验证，会创建样例便签，正式启动不用这个参数。

`--library-preview` 打开不加载便签数据的列表预览。可配合 `--inactive` 检查失焦控件颜色，配合 `--dark` 检查深色外观。`--window-checks` 要求虚拟机标记与共享测试目录，误在主机运行时会直接退出。所有会打开窗口的测试入口都应在虚拟机内执行。

## CI 与发版

向 `main` 推送、创建 Pull Request 或手动运行 `CI` 时，GitHub Actions 自动执行：

- Apple Silicon 和 Intel 两套 Swift 单元测试及原生编辑检查。
- 发版工具测试、Universal 构建、签名校验、ZIP 解压与架构校验。
- 保存测试报告、内测 ZIP、`release.json` 和 SHA-256 校验文件，保留 14 天。

GitHub 托管 runner 本身就是一次性虚拟机，原生编辑检查通过专用脚本执行。它会拒绝开发者主机和 self-hosted runner。跨应用焦点、窗口顺序及实际鼠标交互仍需在 Tart 验证。

发版时更新 `packaging/Info.plist` 的版本号和构建号、补充 `CHANGELOG.md`，合并到 `main`，再推送对应标签：

```sh
git tag -a v0.2.3 -m "Jotlet v0.2.3"
git push origin v0.2.3
```

`Release` 会重新执行完整检查，仅在通过后生成草稿 Release。检查草稿的说明和安装包后，在 GitHub 发布。已有标签失败时，可重新运行工作流；也支持手动选择已有标签。已公开的 Release 不会被流程覆盖。具体步骤和签名范围见 [发版说明](docs/RELEASING.md)。

## 图标素材

应用图标位于 `assets/AppIcon.png`，由内置 ImageGen 生成。完整提示词保存在 `assets/icon-prompt.txt`。工具栏和菜单栏使用系统 SF Symbols。
